Dashboard Dataset Consumption Sheet

A quick decision sheet for consuming governed Metric Views in Databricks AI/BI dashboard datasets.

One-Line Rule

Use a direct Metric View dataset when the whole governed model is safe and useful. Use a SQL dataset over the Metric View when you must restrict, filter, or reshape. Use a custom calculation only for dashboard-scoped logic.

Three Options

D

Direct Metric View

Best for governed self-service. Dashboards can automatically use dimensions, measures, and agent metadata from the Metric View.

Q

SQL Dataset

Best for safe projection. Explicitly select fields and evaluate measures with MEASURE().

C

Custom Calculation

Best for dashboard-local calculations that do not deserve Unity Catalog governance.

Safe SQL Dataset Pattern

Use this when the dashboard should expose only segment-level results. Avoid SELECT *; dashboard viewers and Genie can access dataset results even if fields are not shown in charts.

SELECT
  market_segment,
  order_status,
  MEASURE(total_revenue) AS total_revenue,
  MEASURE(order_count) AS order_count,
  MEASURE(revenue_per_customer) AS revenue_per_customer
FROM <catalog>.<schema>.orders_customer_metric_view
WHERE order_month >= DATE '1997-01-01'
GROUP BY market_segment, order_status;

Promotion Test

Before leaving a calculation in the dashboard, ask: "Would another dashboard, SQL user, alert, or Genie question need this exact meaning?" If yes, move it to the Metric View. If no, keep it as a dashboard custom calculation.
