Freshness and Performance Decision Sheet

A quick guide for deciding whether a slow or stale AI/BI dashboard needs cache tuning, scheduled refresh, a standalone Materialized View, or Metric View materialization.

One-Line Rule

Start with the dashboard layer when the issue is initial load or repeated viewer traffic. Move to physical materialization when the dataset query itself is expensive or must have predictable latency.

Four Levers

C

Dashboard Cache

Databricks dashboards maintain a best-effort 24-hour result cache. It can return stale dashboard results for speed.

S

Dashboard Schedule

Schedules run dashboard dataset SQL ahead of viewers and populate cache, especially useful for published dashboards with shared permissions.

M

Standalone MV

Materialized Views physically store a query result and refresh on a schedule, trigger, or manual command using serverless pipelines.

V

Metric View Materialization

Metric View materialization is experimental and uses aggregate-aware rewrite to route eligible Metric View queries to precomputed results.

Snippets

Standalone Materialized View with predictable refresh:

CREATE OR REPLACE MATERIALIZED VIEW sales_daily_mv
  SCHEDULE EVERY 1 DAY
AS SELECT
  date_trunc('day', order_time) AS sales_date,
  market_segment,
  sum(revenue) AS total_revenue,
  count(*) AS order_count
FROM prod.sales.orders
GROUP BY sales_date, market_segment;

Metric View materialization pattern:

materialization:
  schedule: every 6 hours
  mode: relaxed
  materialized_views:
    - name: revenue_by_segment
      type: aggregated
      dimensions:
        - market_segment
        - order_month
      measures:
        - total_revenue
        - order_count

Pitfalls

Do not confuse cache freshness with source freshness. A refreshed upstream table can still be hidden behind a dashboard cache result, while the generic query result cache is invalidated when underlying data changes.

Do not materialize first. Inspect query history, dataset row count, dataset bytes, and repeated grouping/filter patterns before adding serverless refresh cost.

Metric View materialization is experimental. Verify with EXPLAIN EXTENDED or query profile before assuming query rewrite is active.
