Joined Metric View Metadata Cookbook

A compact pattern for enriching a Databricks Metric View with a customer dimension and AI/BI-friendly semantic metadata.

The Pattern

source

samples.tpch.orders

The fact-like table that owns the order grain and raw measures.

join

samples.tpch.customer

A many-to-one dimension lookup reached through o_custkey = c_custkey.

metadata

Display, format, synonyms

Labels for humans, rendering rules for dashboards, and aliases for Genie.

Create The Enriched Metric View

Replace <catalog>.<schema>. Remove rely if you cannot assert the join uniqueness truthfully.

CREATE OR REPLACE VIEW <catalog>.<schema>.orders_customer_metric_view
WITH METRICS
LANGUAGE YAML
COMMENT 'TPC-H order KPIs enriched with customer metadata.'
AS $$
version: 1.1
comment: Order metrics with customer segmentation and AI/BI metadata.
source: samples.tpch.orders
joins:
  - name: customer
    source: samples.tpch.customer
    on: source.o_custkey = customer.c_custkey
    rely:
      at_most_one_match: true
filter: o_orderdate >= '1995-01-01'
fields:
  - name: order_month
    expr: DATE_TRUNC('MONTH', o_orderdate)
    comment: Month when the order was placed.
    display_name: Order Month
  - name: order_status
    expr: |
      CASE o_orderstatus
        WHEN 'O' THEN 'Open'
        WHEN 'P' THEN 'Processing'
        WHEN 'F' THEN 'Fulfilled'
      END
    comment: Business label for order status.
    display_name: Order Status
    synonyms:
      - status
      - fulfillment status
  - name: customer_name
    expr: customer.c_name
    comment: Customer name from the joined customer dimension.
    display_name: Customer Name
  - name: market_segment
    expr: customer.c_mktsegment
    comment: Customer market segment from the joined customer dimension.
    display_name: Market Segment
    synonyms:
      - segment
      - industry
measures:
  - name: order_count
    expr: COUNT(DISTINCT o_orderkey)
    comment: Count of distinct orders.
    display_name: Order Count
    format:
      type: number
      decimal_places:
        type: exact
        places: 0
      abbreviation: compact
    synonyms:
      - orders
      - number of orders
  - name: total_revenue
    expr: SUM(o_totalprice)
    comment: Sum of order total price.
    display_name: Total Revenue
    format:
      type: currency
      currency_code: USD
      decimal_places:
        type: exact
        places: 2
      abbreviation: compact
    synonyms:
      - revenue
      - sales
  - name: unique_customers
    expr: COUNT(DISTINCT o_custkey)
    comment: Count of distinct customers.
    display_name: Unique Customers
    format:
      type: number
      decimal_places:
        type: exact
        places: 0
      abbreviation: compact
  - name: revenue_per_customer
    expr: MEASURE(total_revenue) / MEASURE(unique_customers)
    comment: Revenue divided by unique customers.
    display_name: Revenue per Customer
    format:
      type: currency
      currency_code: USD
      decimal_places:
        type: exact
        places: 2
      abbreviation: compact
    synonyms:
      - customer revenue
      - revenue per buyer
$$;

Query Patterns

Segment breakdown

SELECT
  market_segment,
  MEASURE(total_revenue) AS total_revenue,
  MEASURE(order_count) AS order_count
FROM <catalog>.<schema>.orders_customer_metric_view
GROUP BY market_segment
ORDER BY total_revenue DESC;

Customer leaderboard

SELECT
  customer_name,
  MEASURE(total_revenue) AS total_revenue
FROM <catalog>.<schema>.orders_customer_metric_view
GROUP BY customer_name
ORDER BY total_revenue DESC
LIMIT 20;

Status by segment

SELECT
  market_segment,
  order_status,
  MEASURE(revenue_per_customer) AS revenue_per_customer
FROM <catalog>.<schema>.orders_customer_metric_view
GROUP BY market_segment, order_status
ORDER BY market_segment, order_status;

Rules To Remember

Concept
Rule
Example
Many-to-one join
Default Metric View join cardinality for fact-to-dimension lookup.
orders -> customer
Join field
Use the join name and dot notation when exposing dimension attributes.
customer.c_mktsegment
rely
Optimization assertion. Use only when the at-most-one-match rule truly holds.
at_most_one_match: true
display_name
Human-readable label that downstream visualization tools can show.
Total Revenue
format
Display rendering rule for number, currency, percentage, byte, date, or datetime values.
type: currency
synonyms
Natural-language aliases that help Genie discover the right field or measure.
sales, segment
