Lesson 0003 - 20 minutes

Add a Customer Join and Agent Metadata

Extend the minimal order Metric View with samples.tpch.customer, then make it clean for dashboards and Genie.

Mission tie-in: this is where a Metric View starts acting like a reusable BI semantic model: it gains customer dimensions, human labels, display formats, and synonyms that consumption tools can understand.

Target Skill

By the end, you should be able to add one many-to-one dimension join, expose joined fields with dot notation, and attach display_name, format, and synonyms metadata to fields and measures.

Primary source: Databricks tutorial: Build a complete metric view with joins. Metadata source: Databricks docs: Agent metadata in metric views. Join source: Databricks docs: Joins in metric views.

The Three Additions

join

Customer Dimension

Join orders to customer on o_custkey = c_custkey. Databricks says joins enrich source rows with related attributes; many-to-one is the default cardinality.

fields

Business Segments

Expose joined columns such as customer.c_mktsegment as fields. Fields remain the query-time grouping and filtering surface.

metadata

Consumption Polish

Add labels, formats, and synonyms so AI/BI dashboards display values cleanly and Genie can match natural-language terms.

The join changes what users can group by. Agent metadata changes whether humans and AI tools can find, read, and trust those fields and measures.

Build It

1

Create the enriched Metric View

Replace <catalog>.<schema>. The rely declaration is an optimization assertion: keep it only when each order really matches at most one customer. Databricks warns that incorrect rely assertions can produce wrong measure results.

CREATE OR REPLACE VIEW <catalog>.<schema>.orders_customer_metric_view
WITH METRICS
LANGUAGE YAML
COMMENT 'TPC-H order KPIs enriched with customer metadata.'
AS $$
version: 1.1
comment: Order metrics with customer segmentation and AI/BI metadata.
source: samples.tpch.orders
joins:
  - name: customer
    source: samples.tpch.customer
    on: source.o_custkey = customer.c_custkey
    rely:
      at_most_one_match: true
filter: o_orderdate >= '1995-01-01'
fields:
  - name: order_month
    expr: DATE_TRUNC('MONTH', o_orderdate)
    comment: Month when the order was placed.
    display_name: Order Month
  - name: order_status
    expr: |
      CASE o_orderstatus
        WHEN 'O' THEN 'Open'
        WHEN 'P' THEN 'Processing'
        WHEN 'F' THEN 'Fulfilled'
      END
    comment: Business label for order status.
    display_name: Order Status
    synonyms:
      - status
      - fulfillment status
  - name: customer_name
    expr: customer.c_name
    comment: Customer name from the joined customer dimension.
    display_name: Customer Name
  - name: market_segment
    expr: customer.c_mktsegment
    comment: Customer market segment from the joined customer dimension.
    display_name: Market Segment
    synonyms:
      - segment
      - industry
measures:
  - name: order_count
    expr: COUNT(DISTINCT o_orderkey)
    comment: Count of distinct orders.
    display_name: Order Count
    format:
      type: number
      decimal_places:
        type: exact
        places: 0
      abbreviation: compact
    synonyms:
      - orders
      - number of orders
  - name: total_revenue
    expr: SUM(o_totalprice)
    comment: Sum of order total price.
    display_name: Total Revenue
    format:
      type: currency
      currency_code: USD
      decimal_places:
        type: exact
        places: 2
      abbreviation: compact
    synonyms:
      - revenue
      - sales
  - name: unique_customers
    expr: COUNT(DISTINCT o_custkey)
    comment: Count of distinct customers.
    display_name: Unique Customers
    format:
      type: number
      decimal_places:
        type: exact
        places: 0
      abbreviation: compact
  - name: revenue_per_customer
    expr: MEASURE(total_revenue) / MEASURE(unique_customers)
    comment: Revenue divided by unique customers.
    display_name: Revenue per Customer
    format:
      type: currency
      currency_code: USD
      decimal_places:
        type: exact
        places: 2
      abbreviation: compact
    synonyms:
      - customer revenue
      - revenue per buyer
$$;
2

Query by joined field

The query sees market_segment as a normal field, even though its expression comes from the joined customer table.

SELECT
  market_segment,
  MEASURE(total_revenue) AS total_revenue,
  MEASURE(order_count) AS order_count,
  MEASURE(revenue_per_customer) AS revenue_per_customer
FROM <catalog>.<schema>.orders_customer_metric_view
GROUP BY market_segment
ORDER BY total_revenue DESC;
3

Query by customer and status

The same governed measures now work at a customer-grain grouping without redefining the KPI.

SELECT
  customer_name,
  order_status,
  MEASURE(total_revenue) AS total_revenue,
  MEASURE(order_count) AS order_count
FROM <catalog>.<schema>.orders_customer_metric_view
GROUP BY customer_name, order_status
ORDER BY total_revenue DESC
LIMIT 20;

Why Metadata Is Not Decoration

For dashboards

Databricks says semantic metadata automatically populates downstream AI/BI dashboards. display_name improves labels, and format controls currency, number, percentage, byte, date, and datetime display.

For Genie

Databricks says synonyms help Genie discover fields and measures from natural language. A user asking for "sales by segment" can map to total_revenue and market_segment.

Retrieval Practice

Classify the YAML property

Use the answer bank. The labels are intentionally one character each.

D: Display
F: Format
S: Synonym
display_name: Total Revenue
currency_code: USD
- sales
abbreviation: compact

Write the joined field expression

Complete the expression for market_segment. Type only the expression, not the field name.
