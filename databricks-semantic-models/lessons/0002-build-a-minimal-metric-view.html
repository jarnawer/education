Build a Minimal Metric View

Create a tiny governed semantic layer over samples.tpch.orders, then query it with MEASURE().

Mission tie-in: this is the first concrete move from Databricks Data Engineering into the semantic model layer: convert raw lakehouse columns into governed fields and measures that dashboards, SQL, and Genie can reuse.

Target Skill

By the end, you should be able to write a minimal Metric View DDL with one source, three fields, four measures, and two valid MEASURE() queries.

Primary source: Databricks docs: Create and edit metric views. Query source: Databricks docs: Query metric views.

The Minimal Mental Model

1

Source

The raw table-like asset. Here: samples.tpch.orders. Databricks requires SELECT privileges on the source.

2

Fields

Scalar expressions users can select, filter, and group by. Example: convert o_orderstatus codes into labels.

3

Measures

Aggregate expressions users evaluate with MEASURE(). Example: SUM(o_totalprice) becomes total_revenue.

A Metric View does not pre-answer one aggregation. It defines allowed business measures and lets the query choose the grouping fields at runtime.

Build It

1

Choose a target name

Use a Unity Catalog schema where you have USE CATALOG, USE SCHEMA, and CREATE TABLE. The docs require a SQL warehouse or compute resource running Databricks Runtime 17.3 or above for creation.

2

Create the Metric View

Replace <catalog>.<schema>, then run the SQL in Databricks SQL Editor.

CREATE OR REPLACE VIEW <catalog>.<schema>.orders_metric_view_min
WITH METRICS
LANGUAGE YAML
COMMENT 'Minimal Metric View for TPC-H order KPIs.'
AS $$
version: 1.1
comment: Minimal order metrics from samples.tpch.orders.
source: samples.tpch.orders
filter: o_orderdate >= '1995-01-01'
fields:
  - name: order_month
    expr: DATE_TRUNC('MONTH', o_orderdate)
    comment: Month when the order was placed.
  - name: order_status
    expr: |
      CASE o_orderstatus
        WHEN 'O' THEN 'Open'
        WHEN 'P' THEN 'Processing'
        WHEN 'F' THEN 'Fulfilled'
      END
    comment: Business label for order status.
  - name: order_priority
    expr: SPLIT(o_orderpriority, '-')[0]
    comment: Numeric priority extracted from the source priority code.
measures:
  - name: order_count
    expr: COUNT(DISTINCT o_orderkey)
    comment: Count of distinct orders.
  - name: total_revenue
    expr: SUM(o_totalprice)
    comment: Sum of order total price.
  - name: unique_customers
    expr: COUNT(DISTINCT o_custkey)
    comment: Count of distinct customers.
  - name: revenue_per_customer
    expr: MEASURE(total_revenue) / MEASURE(unique_customers)
    comment: Revenue divided by unique customers.
$$;
3

Query it by month

Measures must be wrapped in MEASURE(). Databricks documents that MEASURE() inherits the aggregation definition from the Metric View instead of specifying SUM, AVG, or COUNT in the query.

SELECT
  order_month,
  MEASURE(total_revenue) AS total_revenue,
  MEASURE(order_count) AS order_count
FROM <catalog>.<schema>.orders_metric_view_min
GROUP BY order_month
ORDER BY order_month;
4

Query it by status

The same measures can be evaluated at a different grouping level without redefining the KPI.

SELECT
  order_status,
  MEASURE(total_revenue) AS total_revenue,
  MEASURE(revenue_per_customer) AS revenue_per_customer
FROM <catalog>.<schema>.orders_metric_view_min
GROUP BY order_status
ORDER BY total_revenue DESC;

Why This Matters

This small example shows the core semantic-layer move:

o_orderstatus becomes a business field named order_status.

SUM(o_totalprice) becomes a governed measure named total_revenue.

SUM(o_totalprice) / COUNT(DISTINCT o_custkey) becomes revenue_per_customer, reusable across month, status, priority, dashboards, and Genie.

Retrieval Practice

Classify each item

Use the answer bank. The labels are intentionally one character each.

F: Field
M: Measure
DATE_TRUNC('MONTH', o_orderdate)
SUM(o_totalprice)
CASE o_orderstatus WHEN 'F' THEN 'Fulfilled' END
COUNT(DISTINCT o_custkey)

Write the missing query line

Complete the select expression for total revenue from the Metric View. Type only the expression, not the alias.

SELECT
  order_status,
  ______________ AS total_revenue
FROM <catalog>.<schema>.orders_metric_view_min
GROUP BY order_status;
