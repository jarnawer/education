RAG vs GraphRAG Decision Map

A compact reference for choosing the retrieval shape before choosing tools. Use it whenever a stakeholder asks, "Should this be RAG or GraphRAG?"

Baseline RAG

Best for local questions. The user asks for facts or passages likely to live in a small number of nearby chunks. The system retrieves top matching chunks, inserts them into context, and asks the LLM to answer.

Primary source: Lewis et al., 2020.

GraphRAG

Best for global and relationship-heavy questions. The user asks for themes, patterns, communities, connections, or sensemaking across a corpus. The system uses an entity graph, communities, and summaries.

Primary source: Edge et al., 2024/2025.

Core Pipeline Shapes

Baseline RAG documents - chunks - embeddings - vector index query - query embedding - top-k chunks - LLM answer
GraphRAG documents - text units - entities + relations - graph graph - communities - community summaries query - local/global/DRIFT search - LLM answer

Architecture instinct: first classify the question shape. Tool choice comes after that.

Decision Table

Question Shape First Try Reason
"What does policy X say about refunds?" Baseline or hybrid RAG Likely answer exists in a small set of specific chunks.
"Which documents mention customer Y and contract Z?" Baseline RAG plus metadata filters Structured filters narrow the search before semantic ranking.
"What are the main themes in all incident reports?" GraphRAG global search This is corpus-level summarization, not a simple nearest-neighbor lookup.
"How is supplier A connected to risk B?" GraphRAG local or DRIFT search The answer may require traversing entities, relations, and nearby communities.
"What changed since yesterday?" Fresh baseline RAG first Graph indexes can be expensive to rebuild; freshness may dominate.

Failure Modes To Remember

  • Baseline RAG misses global structure when the answer is distributed across many chunks.
  • GraphRAG can be overkill when top-k chunk retrieval answers the question cheaply and accurately.
  • Both fail without evaluation: measure retrieval quality, groundedness, answer usefulness, latency, and cost.
