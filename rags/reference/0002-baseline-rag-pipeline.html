Baseline RAG Pipeline Reference

The two-rail mental model for baseline RAG: one offline pipeline prepares searchable context; one online pipeline turns a user query into grounded output.

Offline Indexing Rail

Goal: convert source data into retrievable context.

01 Load
Read from files, APIs, databases, object stores, or SaaS systems into documents with metadata.
02 Split
Transform documents into chunks or nodes small enough to retrieve and fit into model context.
03 Embed
Create vector representations of chunk meaning so semantic search can work.
04 Store
Persist chunks, embeddings, metadata, document IDs, and version information.

Online Query Rail

Goal: retrieve useful context and synthesize a grounded answer.

05 Query
Receive the user question and optionally rewrite, classify, or route it.
06 Retrieve
Search the index, often with top-k semantic retrieval plus metadata filters or hybrid search.
07 Refine
Rerank, filter, expand, or trim retrieved chunks before they reach the model.
08 Answer
Send question plus selected context to the LLM and return the response with citations when possible.

Chunk or nodeModeled analytical grainIs this unit big enough to preserve meaning and small enough to retrieve precisely?
Embedding modelFeature transformationDoes this representation match the language, domain, and query style?

Diagnostic Map

SymptomStart Looking AtWhy
Correct document never appearsLoading, metadata, permissions, indexingThe evidence may never have entered the retrievable corpus.
Correct document appears, wrong passage selectedChunking, embeddings, top-k, hybrid retrievalThe index may have the source but retrieve the wrong grain.
Good chunks retrieved, answer still wrongPrompt, synthesis, context ordering, model behaviorRetrieval succeeded; generation or instruction following failed.
Answer is good but too slow or costlyStorage, top-k, reranking, context size, model choiceQuality is acceptable; serving economics are the bottleneck.
Fresh content is missingIngestion cadence, incremental updates, invalidationThe offline rail is stale relative to user expectations.

Rule: do not fix a RAG failure with prompt changes until you know whether the right evidence was retrieved.
