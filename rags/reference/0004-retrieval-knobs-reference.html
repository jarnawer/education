Retrieval Knobs Reference

A compact diagnostic sheet for online retrieval tuning in baseline RAG. Use it after checking that the corpus is indexed and the chunk grain makes sense.

Top-k

Controls candidate budget. Raise it when the gold chunk exists but falls below the current cutoff. Lower it when enough evidence is found and excess context hurts precision or cost.

Filters

Enforce constraints. Use metadata or keyword filters for tenant, permission, product, date, language, jurisdiction, source, and version.

Reranking

Prioritizes final context. Use reranking or score cutoffs when a wider candidate set contains the answer but also includes distracting neighbors.

Debugging Algorithm

1. Confirm the answer source was ingested and indexed. 2. Inspect the gold chunk rank for the failed query. 3. If the gold rank is outside top_k, raise top_k and measure recall. 4. If wrong business scope appears, add metadata or keyword filters. 5. If the answer is present but crowded by weak chunks, rerank or cut by score. 6. If no online knob isolates the answer, revisit chunk grain.

Rule: top_k is a recall budget. It does not mean the returned chunks are all safe, sufficient, or correctly scoped.

Senior habit: record the candidate list before and after every retrieval change. Otherwise you cannot tell whether generation improved because retrieval improved or because the model got lucky.
