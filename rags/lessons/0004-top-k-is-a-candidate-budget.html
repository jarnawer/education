Lesson 0004 - 15 minutes - Retrieval tuning

Top-k is a candidate budget, not a relevance guarantee

After you choose chunk grain, the online retrieval path has to decide how many candidates to fetch, which candidates to exclude, and which candidates deserve final context space.

Mission link: senior RAG engineers do not randomly raise top_k. They read the failure symptom, pick the first retrieval knob, and measure whether recall improved without drowning the generator.

1. The Minimum Knowledge

In a vector store index, source text is split into nodes, each node gets an embedding, and a query is embedded so the index can rank chunks by semantic similarity [source].

top_k controls how many of the most-similar chunks are returned after ranking. LlamaIndex calls this top-k semantic retrieval and describes it as the simplest form of vector-index querying [source].

Querying has three stages: retrieval, postprocessing, and response synthesis. Postprocessing can rerank, transform, or filter retrieved nodes; examples include a similarity cutoff, keyword filters, and adding previous or next node context [source].

Evaluation separates recall from precision: recall asks whether correct items were found, while precision asks how much of what you returned was correct [source]. That distinction is the reason top_k tuning must be measured.

2. The Three-Stage Retrieval Model

Retrieve

Fetch an initial candidate set from the index.

Main knob: raise or lower top_k.

Constrain

Exclude candidates that should never be considered.

Main knob: metadata or keyword filters.

Prioritize

Reorder or trim candidates before generation.

Main knob: reranking or score cutoffs.

Use top_k to improve recall, filters to enforce constraints, and reranking to improve precision inside a wider candidate set.

Reference to keep open: Retrieval Knobs Reference.

3. A Tiny Example

A policy assistant answers, "No refund exception found." The correct exception exists in the index, but it is ranked seventh for the query.

Raise top_k

Moving from top_k=3 to top_k=10 may recover the right chunk. That is a recall move.

Risk: more weak chunks compete for context and can confuse synthesis.

Then rerank or filter

If the wider set includes the right chunk plus noise, rerank or apply metadata filters before sending context to the model.

Risk: over-tight filters can remove the answer completely.

4. Retrieval Practice

Choose the first move you would try. Use memory first; then check the reference.

Choice map: Plan A = raise top_k. Plan B = add filters. Plan C = rerank. Plan D = redesign chunks.
The gold answer chunk is usually ranked between 6 and 9, but the system only retrieves 3 chunks.
Relevant chunks are retrieved, but they come from the wrong country and expired policy version.
At top_k=20, the answer is found, but weakly related chunks crowd out the best evidence.
The right document is retrieved, but every chunk mixes five unrelated topics and no ranking setting isolates the answer.
One-minute production habit: for every failed query, log the gold chunk rank. If the rank is outside top_k, tune recall. If it is inside top_k but absent from final context, tune filtering, reranking, or context assembly.
