Lesson 0001 - 12 minutes - Architecture instinct

RAG vs GraphRAG: the first architecture decision

Your first senior-level habit is not choosing a framework. It is classifying the question shape. That one decision prevents expensive over-engineering and weak retrieval systems.

Mission link: you want to become expert enough to design and defend RAG/GraphRAG systems. Today you will learn the first decision boundary.

1. The Minimum Knowledge

The original RAG idea combines a language model's internal, parametric knowledge with external, non-parametric memory retrieved from an index. Lewis et al. describe this as a way to improve knowledge-intensive generation, support provenance, and update knowledge outside the model weights [source].

In practical systems, RAG usually means: load data, split it into chunks or nodes, create embeddings, store them in an index, retrieve relevant context for a user query, then synthesize an answer. LlamaIndex documents these stages as loading, indexing, storing, querying, and evaluation [source].

GraphRAG changes the shape. Microsoft describes it as extracting entities and relationships from text, building a graph, clustering that graph into communities, summarizing those communities, then using graph structures at query time [source]. The GraphRAG paper argues this helps with global questions such as "What are the main themes in the dataset?", where baseline retrieval is not enough [source].

2. The Rule

Use baseline RAG for local evidence. Consider GraphRAG for global sensemaking or relationship traversal.

Baseline RAG question

Shape: "Find the few chunks that answer this."

Example: "What does the contract say about renewal notice?"

Architectural match: chunking, embeddings, metadata filters, hybrid search, reranking.

Use when evidence is likely concentrated.

GraphRAG question

Shape: "Connect many facts across the corpus."

Example: "What are the recurring risk themes across all incident reports?"

Architectural match: entities, relationships, communities, community summaries, graph-aware search.

Use when evidence is distributed.
