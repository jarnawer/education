Lesson 0002 - 15 minutes - Pipeline diagnosis

Baseline RAG as two pipelines

A RAG system is not one magic prompt. It is an offline indexing pipeline plus an online query pipeline. If you can name the rail where a decision belongs, you can debug and improve RAG systematically.

Mission link: senior RAG architects diagnose retrieval systems by component. This lesson gives you the first component map.

1. The Minimum Knowledge

LlamaIndex describes a practical RAG pipeline as five stages: loading, indexing, storing, querying, and evaluation [source]. For architecture work, split those into two rails.

The offline rail prepares data: load source data, transform it into chunks or nodes, create embeddings, and store the resulting index. LlamaIndex explicitly compares ingestion to ETL and says transformations include chunking, metadata extraction, and embedding each chunk [source].

The online rail serves user questions: retrieve relevant documents or nodes, optionally postprocess them, then synthesize an answer. LlamaIndex defines querying as retrieval, postprocessing, and response synthesis [source].

Embeddings are numerical representations of text meaning. A vector index uses them so queries can find semantically similar chunks, often through top-k retrieval [source]. Persisting indexes or using vector stores avoids repeatedly paying the time and cost of re-indexing [source].

2. The Two-Rail Model

Offline indexing rail

Runs before the user asks. Similar to ETL plus serving-index construction.

Load
Read source data and attach metadata.
Split
Create chunks or nodes at the right grain.
Embed
Turn chunk meaning into vectors.
Store
Persist chunks, vectors, metadata, and versions.

Online query rail

Runs when the user asks. Similar to a serving path with retrieval and synthesis.

Query
Accept, rewrite, classify, or route the question.
Retrieve
Fetch candidate chunks from the index.
Refine
Filter, rerank, expand, or trim context.
Answer
Synthesize grounded output from question plus context.
Before changing prompts, inspect retrieval. If the right evidence did not reach the model, generation was never the real bug.

3. Retrieval Practice

Choose the pipeline area where you would start diagnosis. Use memory first; then check the reference.

Choice map: Path A = offline ingestion/indexing. Path B = online retrieval/refinement. Path C = answer synthesis/model behavior.
Users ask about a new policy uploaded this morning, but the answer always says it cannot find the policy.
The correct document is indexed, but retrieved chunks are adjacent to the answer rather than the answer itself.
The retrieved context contains the exact answer, but the final response contradicts it.
The system works, but each deploy spends hours recomputing embeddings for unchanged documents.
One-minute production habit: for any RAG bug report, write three facts before proposing a fix: what was indexed, what was retrieved, and what was generated.
