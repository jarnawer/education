Lesson 0003 - 15 minutes - Retrieval grain

Chunk grain before embeddings

A vector index retrieves chunks, not documents and not abstract ideas. Before asking which embedding model to use, choose the unit of meaning that should be retrievable.

Mission link: senior RAG engineers can defend why their system retrieves at a particular grain. This lesson gives you that design habit.

1. The Minimum Knowledge

LlamaIndex describes ingestion as loading data, transforming it, then indexing and storing it. The transformation stage includes chunking, extracting metadata, and embedding each chunk [source].

When documents become a VectorStoreIndex, they are split into Nodes and each node receives a vector embedding. At query time, the query is also embedded, and the index ranks chunks by semantic similarity [source].

That means chunking is an architecture decision. LlamaIndex says an Index should be complementary to the querying strategy [source]. If your query needs a contract clause, a support answer, or a ticket summary, your chunks should usually preserve that unit of meaning.

2. The Three Knobs

Size

Smaller chunks improve precision. Larger chunks preserve context. Neither is always right.

Question: is the answer buried or fragmented?

Overlap

Overlap protects answers that cross boundaries. It also creates duplicate vectors and repeated context.

Question: are misses caused by chunk edges?

Metadata

Metadata lets retrieval filter by source, date, tenant, permission, product, or jurisdiction before ranking.

Question: should similarity be constrained?

Treat chunks like data-model grain: the smallest stable unit that can answer the target query shape.

Reference to keep open: Chunk Design Reference.

3. A Tiny Example

Imagine a policy corpus. The user asks, "What is the refund window for enterprise customers in France?"

Weak grain

One 2,000-token chunk covers refunds, cancellations, exceptions, regions, and billing disputes.

Problem: top-k may retrieve the right chunk, but the answer is surrounded by noise.

Better grain

One chunk holds the refund clause plus section title, effective date, customer segment, and jurisdiction metadata.

Benefit: retrieval can filter to France and enterprise, then rank a focused clause.

4. Retrieval Practice

Choose the first chunking move you would try. Use memory first, then check the reference.

Choice map: Plan A = split smaller. Plan B = keep larger. Plan C = add context through overlap, title path, or metadata.
The correct chunk is retrieved, but it contains five unrelated policy topics and the answer is easy to miss.

Retrieved clauses are precise, but each clause relies on the definition immediately above it.
Search returns semantically relevant policies, but from the wrong country and effective date.
One-minute production habit: for each target question type, write the ideal retrievable unit before choosing chunk size. Example: "numbered clause with section path and effective date."
